# Captura y revisión del dataset — Fase 03.4-R

Fecha: 25/11/2026. Inventario inicial: **26 originales PNG reales, 7 derivados PNG**, 37 archivos en las carpetas de datos incluyendo metadatos y marcadores. Se creó `.tools/backups/fase03_4R_dataset.zip` y se comprobó cada entrada por SHA-256 antes de editar software. El inventario con hashes está en `evidencias/fase03_4R/preservacion_inicial.json`. Ambos son locales e ignorados por Git. Durante esta fase no se tomó ninguna fotografía física ni se transformaron imágenes del dataset real.

Abra Dataset → Herramientas → **Cobertura, contexto y orientación por archivo…**. La primera pestaña muestra forma/color, totales por figura, colores y total de positivos. Meta orientativa: 50 por combinación, nueve combinaciones, 450 positivos. Para cada combinación procure 10 cerca, 15 a distancia media, 10 lejos, 10 ángulos y 5 con iluminación diferente. La guía no bloquea capturas adicionales ni evalúa automáticamente la diversidad. Las sesiones deben representar tomas independientes, no renombrar una misma ráfaga para fabricar independencia.

Puede escribir distancia, perspectiva, iluminación y tonalidad y pulsar Usar contexto. Son campos opcionales. Las siguientes capturas registran ese contexto y el nombre/perfil visual completo usado. Una ráfaga congela su contexto al iniciarse. Seleccione forma, color y sesión, confirme estado reciente desarmado y reposo, capture originales o inicie la ráfaga. Se conservan las transacciones con journal, cancelación y revisión de seguridad en cada escritura. Un frame repetido no produce otra toma de ráfaga.

Para negativos seleccione `no_objetivo`. Puede indicar un color o `sin_color`. La meta adicional es **100–150 negativos variados**, aparte de los 450 positivos: ropa, mochila, muebles, regiones del fondo y otras figuras. Se registra si existe un candidato coloreado o si es fotografía completa sin candidato. Con un único candidato se puede generar recorte; múltiples candidatos no se etiquetan automáticamente con una selección arbitraria. `sin_color` no es válido para las tres figuras positivas. Las etiquetas son humanas: HSV no reconoce forma.

La revisión de calidad existente conserva advertencias de iluminación, nitidez, resolución, tamaño aparente y duplicados. Aceptar/rechazar/sin revisar no elimina el original y modifica la elegibilidad para divisiones futuras. Una advertencia no equivale a rechazo automático. Los originales reales cuentan desde el manifiesto, excluyendo fixtures, rutas externas, duplicados de ruta y archivos inexistentes. Los negativos se cuentan aparte.

En **Revisar orientación / recorte**, seleccione un archivo: izquierda original crudo, derecha recorte registrado si existe. Para crear una versión normalizada nueva:

1. Examine el original y su orientación; no asuma que todas las capturas antiguas necesitan 270°.
2. Use los metadatos de ese archivo para conservar su transformación registrada, o elija explícitamente 0°, 90° izquierda/derecha o 180°. Si el archivo carece de orientación registrada, la opción de metadatos se rechaza y exige una decisión humana.
3. Confirme Crear derivado. Se crean nuevos PNG bajo `derived/normalized/` y un registro aditivo `metadata/normalizations.jsonl`. No se reescriben el original, el recorte previo, el manifiesto ni el sidecar anterior. Se conserva SHA-256 del original, rotación, inversiones, ROI del recorte, perfil, sesión, clase/color humanos y fecha. La imagen normalizada no aplica ajustes digitales; estos solo influyen en la localización HSV del recorte.
4. Compare el resultado. Seleccione un derivado del desplegable para volver a verlo. Aceptar, Rechazar y Pendiente afectan exclusivamente ese derivado; la revisión del original es independiente. Los estados se guardan transaccionalmente en `metadata/reviews.json`.

Preparar división conserva sesiones completas y agrupa duplicados exactos de originales y recortes, incluidos los nuevos normalizados. Comprueba archivos faltantes, decodificación, etiquetas incompatibles y el hash original que respalda cada normalización. Los derivados rechazados se excluyen. Cada derivado elegible queda junto al original en el mismo conjunto. Requiere al menos tres grupos independientes y las tres figuras positivas en train/validation/test. Si hay negativos, la falta de cobertura de estos en algún conjunto bloquea `training_ready`. Las normalizaciones pendientes y originales sin revisar también lo bloquean. Los porcentajes 70/15/15 son aproximados por grupos, no por archivos individuales.

Capturar, derivar o cambiar revisión invalida una división anterior. No se entrena ningún modelo ni se descarga una CNN. El almacenamiento mantiene la restricción previa de un solo proceso escritor; cierre otra instancia antes de modificar el dataset.
